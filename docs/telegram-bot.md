# Telegram-бот YaSpotSurfer — гид и ТЗ

Дата: 2026-08-23.  
Код бота идёт по шагам B1–B10. CLI остаётся отладочным контуром; matching и запись не дублируем в хендлерах.

Правило matching то же: **неверный auto-match хуже пропуска**. LLM в matching нет.

---

## 1. Зачем бот, если CLI уже умеет то же самое

CLI доказал интеграции и matching. Бот нужен, чтобы:

- провести **боевой** переезд своей медиатеки (~4000 лайков, 51 плейлист) с прогрессом и очередью review в чате;
- не держать в голове флаги `--dest` / `--resume`;
- отдать тот же пайплайн **другим людям**: публичная бета без пейволла; это энтузиаст-проект, не официальный сервис Яндекса/Spotify.

Бот — тонкий адаптер к уже существующим сценариям application-слоя (`scan` / dry-run / `review` / `write_matched_tracks` / плейлисты).

## 2. Как устроен Telegram-бот (для тех, кто никогда их не делал)

### 2.1. Роли

| Кто | Что делает |
|-----|------------|
| **BotFather** (@BotFather в Telegram) | Создаёт бота, выдаёт **токен** `123456:ABC…`. Это пароль к Bot API. Только в `.env`, не в git и не в чат. |
| **Telegram Bot API** | HTTPS API: принять сообщение, ответить, нарисовать кнопки. Документация: [core.telegram.org/bots/api](https://core.telegram.org/bots/api). |
| **Наш процесс** | Python-программа: получает обновления, вызывает application-слой, шлёт ответы. |
| **Пользователь** | Пишет боту в **личке**. Группы в MVP не поддерживаем. |

Создание бота (один раз):

1. В Telegram: `@BotFather` → `/newbot` → имя и username (например `yaspotsurfer_bot`).
2. Сохранить токен в `.env` как `TELEGRAM_BOT_TOKEN`.
3. `/setprivacy` — для лички не критично; бот всё равно только private chat.
4. `/setcommands` — список команд из §6 (удобно в меню клиента).

### 2.2. Как бот узнаёт о сообщениях

Два взаимоисключающих способа ([getUpdates vs webhook](https://core.telegram.org/bots/api)):

| | **Long polling** | **Webhook** |
|--|------------------|-------------|
| Как | Бот сам спрашивает Telegram: «есть новое?» | Telegram шлёт POST на наш HTTPS URL |
| Нужен публичный домен | Нет | Да (HTTPS, порты 443 / 80 / 88 / 8443) |
| Для нас | **Старт и личная отладка** | Когда появится постоянный сервер и OAuth callback |
| Ограничение | Один процесс-поллер; два polling сразу конфликтуют | Пока webhook висит, `getUpdates` не работает |

Недоставленные апдейты Telegram хранит **до 24 часов**.

Для отладки на себе: polling с ноутбука.  
Публичный бот: VPS (или аналог) + публичный HTTPS для OAuth Spotify. Webhook бота — по желанию, не путать с OAuth callback.

### 2.3. Интерфейс, который умеет Telegram

Не сайт. В личке доступно:

- текст до **4096** символов на сообщение;
- **команды** `/start`, `/scan`, …;
- **inline-кнопки** (`callback_data` — максимум **64 байта**, поэтому в кнопку кладём короткий код, а не Spotify URI);
- ссылка `url` — открыть браузер (OAuth Яндекса/Spotify);
- правка того же сообщения (`editMessageText`) — прогресс «1234 / 3996», без спама чата.

**Не путать:** кнопка `login_url` ([LoginUrl](https://core.telegram.org/bots/api#loginurl)) логинит человека **как пользователя Telegram на нашем сайте**. Она **не** подключает Яндекс и Spotify.

**Telegram Web App** (мини-сайт внутри Telegram) в этапе B не делаем: это уже почти dashboard из бэклога C.

### 2.4. Библиотека Python

Рекомендация: **python-telegram-bot** (v21+, `Application`, async).

Почему не писать «голый» `requests` к Bot API: очереди апдейтов, кнопки, job queue для длинной миграции.  
Почему не aiogram: тоже нормальный выбор; PTB чуть прямее стыкуется с «один Application + фоновые jobs». Стек не смешиваем.

Зависимость **не ставим сами**: когда дойдём до кода, пакет пропишем в `pyproject.toml`, установку делаешь ты (`uv add` / `uv sync`).

## 3. Публичная бета, без ограничений доступа

Продуктовое решение (2026-08-23): бот **публичный**. Бета — **без пейволла, allowlist и доната**. Кто написал в личку, может идти по пайплайну (connect → scan → plan → review → write).

Это энтузиаст-проект для личных нужд автора; другим делиться — потому что хочется, не «официальный перенос». В `/start` короткий дисклеймер (неофициально, на свой страх и риск) — **текст, не шлагбаум**: отдельную кнопку «сначала согласись» не делаем.

Юридически дисклеймер не легализует unofficial Music API. Мы просто не притворяемся партнёрами Яндекса/Spotify.

### 3.1. Модель пользователя (с первого коммита)

Ошибка: JSON `.data/*.json` «на одного», потом ломать. Правило: **`telegram_user_id` = арендатор**.

```text
Telegram user.id
        ↓
токены Yandex / Spotify только этого человека
        ↓
те же use cases, что CLI
```

Чужие лайки и токены не пересекаются. Роли «гость / донатер» в бете нет: все пользователи равны.

### 3.2. Монетизация — не сейчас

Обычные донаты (карты / Boosty / что решим) — **идея на потом**, отдельный разговор. Telegram Stars в бету не тащим. В коде B нет `/donate` и флагов оплаты.

Когда вернёмся к теме: доступ уже есть у всех; донат — поддержка автора, не ключ к функциям. Схему тогда спроектируем отдельно.

### 3.3. Что снять тебе как оператору (не кнопки)

Чтобы чужой Spotify **технически** логинился, нужен выход из Dev Mode / **quota extension**. Пока его нет — в `/help` честно пишем, что чужой OAuth может отвалиться. Это запуск, не отмена публичной беты.

Яндекс: легального library API нет ([yandex-public-api.md](yandex-public-api.md)). UX — implicit (вставка URL с token) + дисклеймер в `/start`.

Хостинг для чужих: публичный `https://…/oauth/spotify/callback`.

Нагрузка: очередь jobs, чтобы один dry-run на 4000 не задушил остальных.

### 3.4. Фазы внедрения

| Фаза | Аудитория | Доступ | Хостинг |
|------|-----------|--------|---------|
| **B1** | ты + кто угодно, если токен уже в BotFather | все функции | polling, localhost OAuth ок для тебя |
| **B2** | публичный username | то же | VPS + HTTPS OAuth; Spotify quota — чтобы чужие аккаунты входили |
| **Потом** | донаты как поддержка | функции по-прежнему открыты | стабильный сервер |

### 3.5. Хранение (задел без Postgres)

Для бота сразу **SQLite** (не JSON CLI):

- `users.telegram_id`;
- токены **зашифрованы** ключом из env;
- snapshot / dry-run / review / write checkpoint **на user_id**;
- сессии кнопок review.

Поля оплаты в схему беты не кладём. Postgres — этап C при нагрузке.

Секреты: токен BotFather, Spotify client secret, ключ шифрования — только env. Логи без access_token.

## 4. Как подключают Яндекс и Spotify из чата

В чате нельзя ввести client_secret и нельзя завершить OAuth без браузера.

```text
Пользователь жмёт [Подключить Spotify]
        ↓
Бот шлёт ссылку authorize?…&state=<подписанный telegram_id>
        ↓
Браузер: логин Spotify → redirect на НАШ https://host/oauth/spotify/callback?code=…
        ↓
Сервер меняет code на token, кладёт в БД к этому telegram_id
        ↓
Бот пишет в личку: «Spotify подключён как <display_name>»
```

`state` обязан быть подписан (чтобы нельзя было привязать чужой Spotify к своему Telegram).

**Яндекс:** тот же implicit, что CLI — «открой ссылку, пришли URL с `#access_token=`». Сообщение с токеном не логируем и по возможности удаляем. Другого read-API нет; в `/start` об этом написано.

**VPN:** из РФ Telegram и Spotify часто требуют VPN; Яндекс через тот же VPN часто timeout.
Не советовать «выключи VPN» как основной ответ — иначе бот (polling) и Spotify отвалятся.
Писать про **split tunnel**: `oauth.yandex.ru` / `music.yandex.ru` / `api.music.yandex.net` мимо VPN.
Проверка токена при `/connect_yandex` — только HTTP с timeout (без `Client.init`),
в `asyncio.to_thread`, чтобы polling не зависал. Ретраи выгрузки — в infrastructure.

## 5. Слои (Clean Architecture)

```text
telegram (handlers, кнопки, progress)
    → application (те же сценарии, что CLI)
        → domain (Track, matching)
    → infrastructure
        Spotify / Yandex HTTP
        SQLite user store
        OAuth HTTP callback (отдельный порт, не Bot API)
```

Хендлер **не** вызывает Spotify search напрямую. Длинные операции (scan на 4000, dry-run search, migrate) — **фон** (`JobQueue` / asyncio task): иначе Telegram решит, что бот завис, а чат не будет принимать кнопки.

Прогресс: править **одно** сообщение раз в N треков (например каждые 25) или раз в 5–10 секунд — не каждое совпадение.

CLI не удаляем: им удобно отлаживать matching без Telegram.

## 6. Интерфейс и команды (ТЗ UX)

Язык бота: **русский**. Команды латинские (привычка Telegram).

### 6.1. `/start`

Один экран, функции сразу:

```text
YaSpotSurfer переносит твою музыку из Яндекс Музыки в Spotify.

Это любительский проект, не сервис Яндекса и не сервис Spotify.
Официального способа отдать библиотеку Яндекса другой программе нет.
Пользуешься на свой страх и риск.

Яндекс Музыка: не подключена / подключена
Spotify: не подключён / подключён как <имя>

Как это будет работать: оба аккаунта → бот читает Яндекс →
подбирает треки в Spotify → сначала проверочный плейлист,
в «Любимые» только с твоего согласия.

[Подключить Яндекс]  [Подключить Spotify]
[Собрать список треков]
[Помощь]
```

### 6.2. Меню после scan

Не тащим из черновика ТЗ кнопки «артисты / альбомы / всё» — CLI этого не пишет, matching не для артистов.

```text
В Яндексе: 3996 лайков, 51 плейлист
Международных кодов треков почти нет — ищем по названию и исполнителю.

[Подобрать лайки в Spotify]
[Подобрать плейлисты]
[Разобрать спорные]
[Что сейчас происходит]
```

### 6.3. План (dry-run)

Как CLI, но текстом:

```text
Лайки: подобрали 3996 треков

Нашлось уверенно:  3600
Нужно твоё решение: 280
В Spotify нет:      116

В Spotify уйдут только уверенные совпадения.
Спорные и ненайденные сами не запишутся.

[Сохранить лайки]
[Сначала в проверочный плейлист]
[Разобрать спорные]
```

Проверочный плейлист (`YaSpotSurfer sandbox` / `YaSpotSurfer: <имя>`) обязателен кнопкой даже в боте: первый прогон боевой медиатеки сразу в «Любимые» слишком дорогой. Запись в настоящие лайки Spotify — отдельное подтверждение («напиши СОХРАНИТЬ»).

### 6.4. Review

По одному треку (как в черновике ТЗ §32), не списком из 280:

```text
Яндекс: The Cure — Lullaby

1. The Cure — Lullaby  (0.96)
2. The Cure — Lullaby (Live)  (0.61)

[1] [2] [Пропуск] [Позже]
```

`callback_data` вида `rv:<short>` → строка в SQLite. «Поиск вручную» в B не делаем (нет UI поиска в чате без Web App).

После решения — сразу следующий. `/review` открывает очередь снова. Решения те же, что CLI: `accept` / `skip`, skip сильнее auto.

### 6.5. Запись и отчёт

Прогресс правкой сообщения. В конце:

```text
Готово: лайки

Сохранено: 3600
Уже были:  12
Пропущено: 384  (review без решения + not-found)

Отчёт: not-found можно выгрузить текстом / файлом.
```

Плейлисты: выбор «короткие сначала» / «конкретный kind» / «все с лимитом треков на один запуск» — чтобы не убить Spotify rate limit за вечер. По умолчанию как CLI rehearsal: не все 51 сразу, пока пользователь явно не нажал «все плейлисты».

### 6.6. Команды

| Команда | Смысл |
|---------|--------|
| `/start` | Дисклеймер (текст) + статус связей + меню |
| `/connect_yandex` | Implicit URL |
| `/connect_spotify` | OAuth |
| `/scan` | Snapshot библиотеки Яндекса |
| `/plan` | Dry-run лайков (и опционально плейлистов) |
| `/review` | Следующий спорный трек |
| `/migrate` | Запись; спросить dest sandbox vs library |
| `/playlists` | Копии плейлистов в `YaSpotSurfer: …` |
| `/status` | Есть ли незавершённый job, checkpoint |
| `/cancel` | Остановить текущий job, checkpoint сохранить |
| `/logout` | Удалить токены музыки этого telegram_id |
| `/help` | Пайплайн, matching, неофициальный Яндекс, VPN |

Произвольный текст вне сценария: «напиши /help» — не делаем свободный чат-бот.

## 7. Возможности

### Сейчас в продукте (CLI) — бот должен уметь то же

- Connect Yandex (личный implicit) и Spotify OAuth
- Scan
- Dry-run + resume
- Review accept/skip
- Запись лайков в песочницу или Liked Songs
- Копии плейлистов
- Ретраи сети, кэш raw-плейлистов Яндекса

### Этап B бота (этот ТЗ)

- Публичная бета без пейволла: любой в личке
- Короткий дисклеймер в `/start` (не гейт)
- Прогресс и отмена job, очередь при нескольких пользователях
- Подтверждение боевой записи
- SQLite на пользователя
- Фоновые jobs

### Не в B (бэклог / C или «нет»)

- Донаты / пейволл (обычные платежи; отдельный разговор)
- Артисты, альбомы, «перенести всё одной кнопкой» без плана
- Двусторонняя синхронизация, continuous sync
- LLM-matching, ручной поиск Spotify в чате
- Группы, каналы, инлайн-режим в других чатах
- Web App / сайт
- Подписка, Telegram Stars как обязательный контур
- Откат уже записанных лайков Spotify одной кнопкой

## 8. Ограничения (продукт и платформа)

| Ограничение | Следствие |
|-------------|-----------|
| Нет official Yandex library API | Дисклеймер в `/start` + unofficial implicit |
| Spotify Dev Mode | Пока нет quota extension, чужой OAuth не взлетит — это задача запуска, не отмена публичности |
| Search limit ≤ 10, запись URI по одному | Полный dry-run 4000 — десятки минут; прогресс обязателен |
| 429 Spotify / timeout Яндекса | Resume + понятные сообщения про VPN |
| Сообщение 4096 символов | Отчёт файлом, не простынёй |
| callback_data 64 байта | Состояние review в БД |
| ~1 бот-процесс на polling | Не два ноутбука с одним токеном |
| Matching auto ≥ 0.90 | Много review — это норма, не баг |
| Premium / Dev Mode Spotify | Без Premium запись может быть запрещена |

## 9. Безопасность

- Бот отвечает только в **private chat**; `chat_id == user_id`.
- Сообщения с yandex token удалять после разбора; не цитировать token в ответе.
- `/logout` и смена аккаунта не оставляют чужой snapshot в сессии.
- Один активный тяжёлый job на пользователя (не два migrate параллельно).
- Healthcheck без секретов.

## 11. Решения, которые нужно подтвердить до кода

Предлагаемые значения по умолчанию (можно возразить):

1. Стек хендлеров: **python-telegram-bot** v21+.
2. Хранение сразу **SQLite**, не JSON из CLI.
3. Бета **публичная, без ограничений доступа** (нет allowlist, нет доната).
4. Яндекс: **вставка implicit URL**; в `/start` короткий дисклеймер-текст, не гейт.
5. Первая запись: **песочница**, боевые лайки — фраза-подтверждение.
6. Плейлисты: пачками / по выбору, не все сразу по умолчанию.
7. Артисты/альбомы/Web App — **не делаем** в B.
8. Донаты (обычные платежи) — **бэклог**, отдельный разговор. Stars в бету не берём.
9. Spotify quota extension — пункт **запуска для чужих аккаунтов**, не отмена публичной беты.

Когда этот список ок — можно начинать B1 (`/start` + `/help`, без музыки).
